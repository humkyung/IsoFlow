### M1 에서 실데이터로 발견한 것

1. **올렛은 좌표 일치로 절대 연결되지 않는다.** 모재 배관의 *끝점이 아니라 중간*에 용접되기 때문이다.
   → `BranchAttacher` 가 차수 1인 접합점을 배관 선분 위에서 찾아 붙인다. 없었으면 라인이 두 조각으로 보였다.
2. **보어가 붙은 `CENTRE-POINT` 는 헤더 접속점이다.** 엘보/티의 `CENTRE-POINT` 는 호 중심이라 보어가 없다.
   코퍼스 전수 확인: 보어 있는 CENTRE-POINT 는 올렛 2건뿐, 엘보 37 / 티 17 은 모두 보어 없음.
   → `Port.isConnectable()` 이 이 판별자를 쓴다.
3. **`MATERIAL-LIST EXCLUDE` 컴포넌트는 MATERIALS 섹션에 없다.** ITEM-CODE 참조 검사에서 제외해야 한다.
4. **종단 선언이 빠진 열린 분기가 실재한다** (012 의 TEE 분기 1건). 정상 데이터로 간주하지 않고
   `DANGLING_PORT` 로 보고한다 — 테스트는 "0건"이 아니라 "빠짐없이 보고되는가"를 검증한다.
5. 좌표 오차가 최대 0.07mm 수준으로 존재한다 → tolerance 1mm 병합이 필수.

### 미결 사항
- [ ] 저장소 코퍼스는 **22개 중 3개만** 포함했다(`001` 플랜지·용접, `006` 올렛, `012` 리듀서·티).
      실제 프로젝트 도면이라 전부 넣지 않았다. 전량 포함할지는 확인 필요.

### 설계 결정
- **형상 결정은 엔진 책임.** 백엔드가 `shape` 를 정해 내려보내고 프론트는 그대로 그린다.
  프론트가 컴포넌트 타입에서 다시 추론하면 새 타입 지원 시 규칙이 두 곳으로 갈라진다.
- **메시가 아니라 좌표를 보낸다.** 지오메트리를 직렬화하면 payload 가 수십 배가 되고 LOD 조정도 못 한다.
- **영속화는 아직 없다.** import 는 무상태(파싱 → Scene3D 반환)다. DB 준비 후 이 응답을 감싼다.

### M2 에서 고친 것
1. **`OVERCROWDED_JOINT` 오탐** — 올렛 지점은 (파이프 끝 + 파이프 끝 + 올렛 접속점)으로 차수 3이 정상이다.
   기대 차수를 `2 + 분기포트수` 로 바꿨다.
2. **405 가 500 으로 뭉개짐** — `@ExceptionHandler(Exception)` 만 두면 프레임워크 예외까지 삼킨다.
   `ResponseEntityExceptionHandler` 를 상속하고 `ErrorResponse` 는 상위로 넘긴다.
   (상속 시 `MaxUploadSizeExceededException` 은 `@ExceptionHandler` 추가가 아니라 **오버라이드**해야 한다 —
    중복 매핑이면 컨텍스트가 아예 뜨지 않는다.)

### 편심 리듀서 (2026-08-02)
- **PCF END-POINT 에 편심량이 이미 들어 있다.** 코퍼스 7개 파일 전부에서 작은쪽 중심이 평평한 면
  방향으로 `(OD_large − OD_small)/2` 만큼 어긋나 있었다 (20"×14" → 76.2mm, 6"×4" → 27.0mm,
  2"×1" → 13.46mm). 그래서 `FLAT-DIRECTION` 은 중심을 옮기는 값이 아니라 **런 축을 되찾는** 단서다.
- 두 중심을 그냥 이으면 **축과 양 끝면이 함께 기울어져**(20"×14" 기준 8.5°) 접속 배관과 쐐기 틈이
  생기고 평평한 면이 없다. 중심선에서 편심 성분을 빼 런 축 `a = (P_small − P_large) − u·(r_L − r_S)`
  를 구하고, 양 끝면을 `a` 에 수직인 평행면으로 둔다. 렌더 반지름(보어 기준)으로 계산하므로
  `u` 쪽 모선이 정확히 평평해진다.
- `Shape3D` enum 은 늘리지 않았다 — 엘보의 `angleDeg` 처럼 **형상 수식자 필드**로 처리했다.
- 런이 `FLAT-DIRECTION` 축과 나란하면(수직 배관) 편심 방향을 정할 수 없어 동심으로 낮춘다.
  코퍼스에는 그런 사례가 없고 값도 UP/DOWN 뿐이다.
- 편심인데 `FLAT-DIRECTION` 을 못 읽으면 `ECCENTRIC_FLAT_UNKNOWN` 경고를 남긴다.

### 앵글 밸브 (2026-08-02)
- `VALVE-ANGLE` 은 두 END 가 **90° 로 꺾여** 있고 CENTRE 가 그 모서리다 (PSV-1707A: 수평 96mm + 수직 87mm).
  `BODY` 로 내려 두 END 를 직선으로 이으면 모서리를 가로질러 경로를 벗어난다.
- `Shape3D.VALVE_ANGLE` 을 추가하고 **END(굵음) → CENTRE(가늚) 원뿔 2개**(보타이)로 그린다.
  다리마다 자기 END 의 보어를 쓴다 — 1"×0.75" 처럼 양쪽 구경이 다른 밸브가 있다.
- **인라인 `VALVE` 24개도 CENTRE 를 갖는다**(두 END 의 중점). 그래서 "CENTRE 유무"로는 구분할 수 없어
  원문 키워드 `VALVE-ANGLE` 로 판정한다 — `ComponentType` 이 VALVE-ANGLE/3WAY/4WAY 를 VALVE 로 묶기 때문이다.
  인라인 밸브 형상은 그대로 두기로 했다(사용자 결정).
- CENTRE 가 없으면 엘보와 같은 방식으로 `BODY` 직선으로 낮춘다 — 없는 모서리를 지어내지 않는다.
- 번들 코퍼스 3개에는 밸브가 하나도 없어 백엔드 테스트는 실 도면 좌표로 **합성**했다
  (실제 프로젝트 도면이라 PCF 를 더 넣지 않았다).

### 엘보 접합부 (2026-08-02)
- **원호를 `CatmullRomCurve3` 로 근사하면 안 된다.** 닫히지 않은 스플라인은 끝점을 반사해 보정하므로
  첫 점의 접선이 참 접선이 아니라 **첫 현(chord) 방향**이 된다 — 호 분할각의 절반만큼 어긋난다.
  `TubeGeometry` 는 그 접선에 수직으로 끝면을 만들기 때문에 끝면이 그대로 기운다.
- 실측(반지름 177.8mm · 90° 를 16 분할): 끝면이 **2.81° 기울어 접합면에서 ±8.71mm** 어긋났고,
  반지름도 177.59~177.80 으로 갉여 있었다. 배관과 엘보 사이에 쐐기 모양 틈이 보인다.
- `ArcCurve3`(해석적 원호 + 해석적 접선)로 바꿔 축방향 어긋남 0.00mm, 반지름 177.80 정확,

  ② 배관 테두리에서 엘보 정점까지 최대 거리가 0.5mm 미만인지 본다 (고치기 전 값: 2개 / 8.71mm).

### 버터플라이 밸브 · 가스켓 (2026-08-02)
- **웨이퍼형은 몸통만 그리면 플랜지와 구분이 안 된다.** 14" 기준 길이 78mm 에 지름 480mm 라
  납작한 원반이고, 양옆 플랜지와 굵기가 같다. `Shape3D.VALVE_BUTTERFLY` 로 분리해
  **몸통 + 스템 + 기어박스 + 핸드휠**(플랜트 3D 모델의 통상 표현)을 만든다.
- **스템 방향은 PCF 가 알려 준다** — `SPINDLE-DIRECTION` (코퍼스: UP 14 · WEST 6 · EAST 3 · NORTH 2).
  `Axis6.fromName` 으로 읽고 `Component3D.spindleDirection` 으로 내려보낸다.
  플랜트 좌표계는 X=동 / Y=북 / Z=위다. 방향을 모르면 `BODY` 로 낮춘다 — 지어내지 않는다.
- **버터플라이 판정은 SKEY 로 한다** — skey-table 의 `VY**` / `ZB**` → `VALVE_BUTTERFLY` 가 단일 출처다.
  `PCF_TYPE` 폴백(`VALVE`→`VALVE_GATE`)으로 찾힌 경우는 제외해야 SKEY 없는 밸브가 오인되지 않는다.
  다른 밸브 20여 개는 손대지 않았다(사용자 결정).
- 조작부 치수는 `primitives3d.BUTTERFLY` 에 **몸통 반지름 대비 배율**로 모아 뒀다 — 보어가 커지면 같이 커진다.
- **가스켓을 3D 에서 그리기로 바꿨다**(`GASKET`: `NONE` → `BODY`). 안 그리면 두께만큼 실제로 빈 틈이
  보인다 — P1201-001 에서 밸브 아래 4.5mm 가스켓 자리가 그대로 구멍이었다.
  위쪽은 밸브와 플랜지가 `z=586.5` 를 공유하고 가스켓이 없어 멀쩡했던 것이라, 좌표 오류가 아니었다.
  **2D 는 그대로다** — skey-table 의 `notRendered` 에 GASKET 이 있고 그건 도면 규칙이다.

  똑같아서 스템이 없으면 구분되지 않지만, 게이트는 몸통 자체가 보타이라 조작부만 빠지면 된다.

### 글로브 밸브 (2026-08-02)
- **형상 근거는 2D 심볼 라이브러리다.** `symbols-2d.json` 에서 `VALVE_GATE` 는 보타이,
  `VALVE_GLOBE` 은 **같은 보타이 + 가운데 채운 원**(`r=0.19`, `role: solid`),
  `VALVE_BALL` 은 같은 자리에 **빈 원**(`r=0.27`)이다. 3D 도 이 규칙을 그대로 옮겨
  글로브 = 게이트 보타이 + **중앙 구(球)** 로 만들었다 — 임의로 정한 모양이 아니다.
- 코퍼스의 글로브(P1101-054, 3" `VG**`)도 BB.OS&Y 라 조작부는 게이트와 완전히 같다.
  그래서 상수를 `GATE_OPERATOR` → `OSY_OPERATOR`, `GATE_WAIST_FACTOR` → `BOWTIE_WAIST_FACTOR`
  로 바꿔 두 밸브가 함께 쓴다. 렌더 분기도 `case VALVE_GATE: case VALVE_GLOBE:` 로 합쳤다.
- 구 반지름은 `GLOBE_BULB_FACTOR = 0.75` (END 반지름 대비) — 허리(0.45)보다 커야 밖으로 드러나고
  END(1.0)보다 작아야 몸통을 벗어나지 않는다. 2D 가 원을 보타이 안에 넣는 것과 같은 조건이다.

### 볼 밸브 (2026-08-02)
- **2D 규칙을 그대로 옮길 수 없는 경우다.** 2D 는 글로브=채운 원(0.19) / 볼=빈 원(0.27) 로 가르는데
  **3D 에는 채움·윤곽 구분이 없다.** 구 크기만 바꾸면 글로브와 사실상 같은 형상이 된다.
- 그래서 **조작부로 가른다** — 볼은 90° 회전이라 실물에서도 요크·핸드휠이 아니라 **레버**가 달린다.
  짧은 스템(1.8배) + 배관 축 방향으로 누운 막대(반길이 1.6배)라 핸드휠(원반)과 실루엣이 확연히 다르다.
  구는 `BALL_BULB_FACTOR = 0.85` 로 글로브(0.75)보다 조금 키워 2D 의 반지름 차이도 반영했다.
- **레버는 스핀들에 수직이어야 한다.** 배관 축을 그대로 쓰지 않고 스핀들 성분을 뺀 뒤 쓴다
  (`ballLever`). 배관 축과 스핀들이 나란하면 방향이 정해지지 않아 레버를 그리지 않는다.
- 렌더 분기는 `case VALVE_GATE: case VALVE_GLOBE: case VALVE_BALL:` 하나로 합쳤다 — 보타이 몸통이
  공통이고 구 유무·조작부만 다르다.
- ⚠ **코퍼스에 볼 밸브(`VB**`)가 하나도 없다.** 실 좌표로 검증하지 못했고 단위 테스트로만 확인했다.

### 체크 밸브 (2026-08-02)
- 2D 심볼이 보타이가 아니다 — **유동 방향으로 향한 원뿔 + 꼭짓점의 시트 판**이고
  심볼을 관통하는 중심선이 있다. 3D 도 그대로 옮겼다(배관 굵기 몸통 + 원뿔 + 시트 원반).
- **`FLOW` 규약: `FLOW n` = n 번째 END-POINT 로 향해 흐른다** (1-base). 사용자 확인을 받은 값이다.
  해석은 `Scene3dBuilder.flowToEnd` <b>한 곳</b>에만 있고, 프론트에는 **포트 ordinal** 로만 내려간다
  (`Component3D.flowToEnd`) — PCF 규약이 두 계층으로 갈라지지 않게 했다. 뒤집어야 하면 그 메서드만 고친다.
- `FLOW 0`(미지정)·`FLOW 3`(END 가 없는 번호)·속성 없음 → 방향을 모르므로 **`BODY` 로 낮춘다**.
  체크는 방향이 형상의 전부라, 거꾸로 그리느니 생략하는 편이 낫다.
- ~~코퍼스에 체크 밸브가 없다~~ → **P1102-205 에서 발견**(1" `CK**` BC.SWING, FLOW 1).
  같은 파일의 플러그(FLOW 2)·FLOW-ARROW(FLOW 2)와 함께 보면 셋 다 **+X 로 일치**한다 —
  규약이 컴포넌트 종류를 넘어 자기모순이 없음을 확인했다.

#### 형상 재작업 (2026-08-02, 같은 날)
- **2D 심볼을 3D 로 그대로 밀어낸 것이 잘못이었다.** 원뿔+시트 선을 회전체로 만들면
  "깔때기에 목걸이를 끼운" 모양이 되어 실물과 딴판이다. 2D 심볼은 도면 기호이지 형상 도면이 아니다.
- 웹 확인 결과 **스윙 체크(BC.SWING)의 표준 형상은 배럴 몸통 + 볼트 보닛(캡)** 이고 스템·핸드휠이 없다.
  그대로 바꿨다. 캡은 `perpendicularUp` 으로 위를 향하고(수직 배관이면 +X 로 넘어감),
  유동을 알면 **상류 쪽으로 밀어** 힌지 위치를 나타낸다 — 이것이 방향 단서가 된다.
- 그래서 **유동을 몰라도 `VALVE_CHECK` 를 유지**하도록 판정을 완화했다(전에는 `BODY` 로 낮췄다).
  배럴+캡은 방향 없이도 성립하고, 방향은 캡 위치로만 쓰인다.

### 플러그 밸브 (2026-08-02)
- 2D 가 볼(원) 자리에 **사각형**을 넣어 가르므로, 3D 도 구 대신 **스핀들 축을 따르는 테이퍼 원뿔대**로 갈랐다

- 렌더 분기는 이제 `VALVE_GATE / GLOBE / BALL / PLUG` 넷이 한 case 를 공유한다 —
  보타이가 공통이고 가운데(없음·구·테이퍼)와 조작부(요크·레버)만 다르다.

### M3 에서 고친 것 (전부 테스트가 잡아냈다)
1. **SVD 분해 관계식 오류** — `M = R(φ)·diag·R(θ)^T` 가 아니라 `R(φ)·diag·R(θ)` 였다.
   원 파라미터 대응도 `t-θ` 가 아니라 `t+θ`. 수치 검증 테스트가 아니었으면 못 잡았다.
2. **SVD 반사 소실** — 음의 특이값을 `abs` 로 지우면 거울상이 사라져 호 방향이 뒤집힌다.
   `ry=|sy|` 로 두고 매개변수 부호로 흡수하도록 `Svd2.param()` 에 모았다.
3. **엘보가 항상 사선으로 오검출** — END 두 개를 직접 이으면 언제나 대각선이라
   길이 압축이 통째로 무력화됐다. `CenterlineSegments` 도입으로 해결.
4. **`type` 판별자 직렬화 누락** — record 는 인터페이스의 `type()` 을 프로퍼티로 노출하지 않아
   `As.EXISTING_PROPERTY` 로는 아무것도 안 나간다. `As.PROPERTY` 로 변경(회귀 테스트 추가).
5. **`Diagnostic` NPE** — `Map.copyOf` 가 null 값을 거부해 SKEY 없는 컴포넌트에서 터졌다.
6. **종단 표시 SKEY 미해결 경고** — `skey-table` 의 `notRendered` 목록을 지키지 않았다.

2. **런/분기를 레코드 코드로 정하면 안 된다** — 실샘플에서 런이 45+47, 분기가 46 이었다.

비트마스크로 보인다. 추측해서 채우면 BOM 수량과 3D 반지름이 조용히 틀리므로
**비워 두고 `IDF_BORE_UNRESOLVED` 진단 + 원문을 `IDF-BORE-FIELD` 속성에 보존**한다.

### 치수 대상 노드 필터링

등각도는 **중심선 교점(엘보 모서리) 사이**를 잰다. 엘보의 접점(탄젠트 포인트)은 치수 대상이 아니다.
필터가 없으면 PCF 는 엘보 다리 길이(533)가, IDF 는 17mm 가 도면을 뒤덮는다.

`DimensionPlanner.condense()` 규칙:
1. 인접 구간 중 하나라도 **ELBOW/BEND** 소유면 그 접점을 버린다
2. 칸 길이가 `MIN_INTERVAL_MM`(50mm) 미만이면 이웃에 합친다
3. 런의 양 끝은 항상 남긴다
4. **버린 점의 길이는 이웃 칸에 더해 구간 합계를 보존한다**
5. **엘보 다리만으로 이루어진 런은 치수를 만들지 않는다** — 잴 구간이 아니다

효과 (실 코퍼스):

| 입력 | 수정 전 | 수정 후 |
|---|---|---|
| PCF 006 | 533·601 반복 + 2488 / 1727 / 10748 | 533·601 사라지고 3021 / 2260 / 11281 로 흡수 |
| IDF 012 | `17` 이 20여 개 | 14854 / 5913 / 5203 / 4661 / 3787 / 2632 … |

밸브·플랜지 같은 부품 경계는 그대로 치수 노드로 남는다(테스트로 고정).

### 스타일 설정 시스템

코드 곳곳에 흩어져 있던 도면 상수를 `engine/style/IsoStyle` 한 곳으로 모았다.
JSON 그대로 주고받으며, **빠진 항목은 `withDefaults()` 가 기본값으로 메운다** — 부분 설정만 보내도 된다.

| 묶음 | 항목 |
|---|---|
| `sheet` | 용지 규격(A4/A3/A2/A1) 또는 직접 지정, 여백, 표 영역 폭, 타이틀 블록 높이 |
| `symbols` | 심볼 크기 비율, 최소 크기 |
| `dimensions` | 소수 자릿수, 최소 칸(절대/비율), 치수선 간격, 겹칠 때 밀어내기, 문자 높이 |
| `compression` | 비축척 사용 여부, 압축 시작 길이 |
| `display` | 치수·용접번호·좌표태그·연속표기·노스애로우·라인번호·사선삼각형·자재표 on/off |

- **기본값은 도입 전 동작과 같다.** 요소 개수·치수 문자·경계가 모두 일치하는지 테스트로 고정했다.
- 치수 필터의 `MIN_INTERVAL_MM` 고정값을 `max(minIntervalMm, 도면크기 × minIntervalRatio)` 로 바꿨다.
  큰 도면일수록 임계가 커져 잔치수가 남지 않는다.
- API: `POST /api/isometrics/{generate,export}` 에 선택 파라미터 `style`(JSON 문자열),
  `GET /api/styles/default` 로 기본값 조회. 파싱 실패는 `INVALID_STYLE` 로 되돌려 준다
  (조용히 기본값으로 넘어가면 설정이 왜 안 먹는지 알 수 없다).
- 프론트는 리본 **[스타일 설정]** 대화상자에서 편집하고 localStorage 에 저장한다.
  적용하면 곧바로 다시 생성하고, 내보내기에도 같은 스타일을 보낸다 — 화면과 종이가 같아야 한다.
- 프론트가 기본값을 복제해 두므로 `IsoStyleContractTest` 가 `src/types/isoStyle.ts` 를 읽어
  백엔드 기본값과 대조한다(그룹별 값·항목 수). 이 TS 파일은 gradle test 입력으로 선언해
  프론트만 고쳐도 테스트가 다시 돈다.

**작업 중 잡은 것**: `SheetComposer` 의 여백/표폭/타이틀 높이를 가변 static 으로 뺐다가
동시 요청에서 서로 덮어쓰는 구조가 됐다. `Layout` 레코드를 파라미터로 넘기도록 되돌렸다.

## 라벨 겹침 회피 — 선분 기반 판정

기존 `LabelPlacer` 는 상자끼리만 비교했고, **중심선은 아예 등록하지 못했다.**
등각도의 중심선은 대부분 대각선이라 경계 상자가 도면 절반을 덮는다 —
상자로 등록하면 라벨이 놓일 자리가 남지 않아 전부 강제 배치로 떨어지고,
결국 회피가 없는 것과 같아진다.

그래서 **선분 점유**를 따로 두고 상자-선분 교차를 Liang-Barsky 절단으로 판정한다.
선분끼리는 서로 막지 않는다 — 도면 선끼리는 원래 교차한다.

효과 (실 코퍼스, 문자 상자가 중심선을 가로지르는 개수):

| 입력 | 수정 전 | 수정 후 |
|---|---|---|
| PCF 001 | 0 | 0 |
| PCF 006 | **7** | **0** |
| PCF 012 | 0 | 0 |

회귀 테스트로 고정했다 (`labelsAvoidCenterlines`).

## 사용자 정의 심볼 확장

- **엔진**: `SymbolSet.withOverlay(json)` 가 기본 세트 위에 사용자 JSON 을 덮는다.
  같은 이름이면 교체, 새 이름이면 추가. 기본 세트는 건드리지 않으므로 요청마다 다른 세트를 써도 된다.
- **검증**: `validateOverlay(json)` 가 지원하지 않는 요소 type, 없는 형상을 가리키는 SKEY,
  빈 elements 를 모아 돌려준다. **업로드 시점에 막지 않으면 도면에서 심볼이 조용히 빠지고,
  그때는 원인을 찾기 어렵다.**
- **저장**: `V2__add_user_symbol_set.sql` + `POST/GET/DELETE /api/symbol-sets`.
  생성·내보내기에 `symbolSetId` 를 주면 그 세트로 그린다.
- DB 없이 기동한 프로파일에서는 저장소 빈이 없다. 이때 세트를 고르면
  **조용히 기본 세트로 넘어가지 않고** `SYMBOL_STORE_UNAVAILABLE`(503) 로 거절한다.

## 시트 분할 — 기구는 완성, 기준은 미결

`SheetSplitter` 가 **배관을 따라 걸으며** 컴포넌트를 통째로 묶는다.
공간을 격자로 자르면 경계의 엘보·밸브가 반쪽만 남기 때문이다.

- 치수는 시트 경계에서 잘린다. **각 칸은 정확히 한 시트에만 들어가므로 합계가 보존된다**
  (테스트로 고정). 경계점은 양쪽 컴포넌트가 각자의 Port 로 갖고 있어
  **객체가 아니라 좌표로 판정**해야 한다 — 처음에 객체로 했다가 반대편 칸이 통째로 사라졌다.
- 용접 번호는 라인 전체를 세면서 매기고 자기 장의 것만 그린다.
  장마다 1번부터 다시 매기면 같은 용접이 장마다 다른 번호를 갖는다.
- 자재표는 **1장에만** 얹는다. 장마다 반복하면 발주 수량으로 오독된다.
- PDF 는 시트당 한 페이지, DXF 는 페이지 개념이 없어 **나란히 배치**한다.
- 뷰어는 `scenes[]` 를 받아 하단에서 장을 넘긴다.

### 분할 기준 — 라벨 밀도

**언제 나눌지는 그려 보기 전에는 알 수 없다.** 그래서 한 장으로 그려 보고,
라벨이 너무 많이 밀려나면 장수를 늘려 다시 그린다(`maxSheets` 까지). 더 나눠도 나아지지 않으면
더 나은 쪽을 남기고 멈춘다. 버려진 시도의 진단은 결과에 섞지 않는다.

- `sheet.maxLabelCrowding` (기본 **0.15**) — 자리를 못 찾아 겹친 채 놓인 라벨 비율
- `sheet.maxSheets` (기본 **6**) — 상한. 폭을 1/k 로 줄여도 실제 장수는 더 나올 수 있어
  **k 가 아니라 나온 장수로** 지킨다

**밀도 지표를 두 번 고쳤다.** 처음에는 `forceOccupy` 시점에 `isFree` 로 되짚어 셌는데,
러닝 치수의 이웃 칸끼리 붙어 있는 것까지 실패로 잡혀 실 코퍼스가 0.35~0.68 로 나왔다.
그건 원래 나란히 놓이는 것이지 회피 실패가 아니다.
**후보를 모두 시도하고도 못 찾은 경우만** 호출측이 알려 주도록 바꾸니 코퍼스 5건 모두 0.00 이 됐다
— 즉 실제 도면은 기본 설정에서 한 장 그대로다(골든과 일치).

| 입력 | 라벨 | 배치 실패 | 비율 |
|---|---|---|---|
| PCF 001 / 006 / 012 | 12 / 28 / 14 | 0 | 0.00 |
| IDF 012 / 014 | 32 / 16 | 0 | 0.00 |

기준이 실제로 걸리는지는 합성 도면(4m 구간에 용접 220개)으로 확인했다 — 자동으로 나뉜다.

### 실 라인 육안 검증 (2026-08-02)

`AViewer/Projects` 실 PCF **22건 전부**의 라벨 밀도를 쟀다. 020 만 0.050 이고 나머지는 전부 0.000 —
**기본 설정(0.15)에서 자동으로 나뉘는 실 라인은 없다.** 가장 큰 020(컴포넌트 41개)을
범위 상한으로 강제 분할해 SVG 를 렌더해 눈으로 확인했다.

| 확인 | 결과 |
|---|---|
| 시트 1/2 | 도곽·타이틀(SHEET 1/2)·BOM/절단/용접 리스트, 경계에 `-> SHEET 2` |
| 시트 2/2 | `<- SHEET 1`, 표 없음, 치수 8289, 좌표 태그·노스애로우 정상 |
| 치수 합계 | 1장 28151 = 2장 19862 + 8289 ✓ (3분할도 14248 + 13903 = 28151 ✓) |
| 컴포넌트 절단 | 없음. 각 그룹은 좌표로 이어진 한 덩어리 |

**육안 검증에서 결함 2개를 잡았다.**

1. **흐름 화살표가 혼자 한 장을 차지했다.** `FLOW-ARROW` 는 어떤 포트와도 좌표를 공유하지 않아
   연결 차수가 0 이고, 걷기 출발점(가장 낮은 차수)으로 뽑혀 첫 그룹이 그것 하나로 닫혔다.
   → 차수 0 인 컴포넌트는 걷기에서 빼고, 그룹이 정해진 뒤 **가장 가까운 그룹에 얹는다**.
   (골든이 이 변경을 잡았다 — 확인해 보니 요소·경계는 그대로고 순서만 바뀌어 갱신했다)
2. **표가 없는 2장부터 우측 표 영역이 통째로 비었다.** 자재표는 1장에만 얹는데
   `SheetComposer` 는 표시 설정만 보고 칸을 잡고 있었다. → 표가 실제로 있을 때만 잡는다.
   종이 우측 40% 가 살아나 도면이 그만큼 커졌다.

검토용 SVG 렌더러도 함께 고쳤다 — 폴리곤을 무조건 검게 채워 도곽이 도면을 덮고 있었다.
이제 Scene 의 스타일을 따른다.

### 시트 균등 배분 (2026-08-02)

기준만으로 그리디하게 채우면 앞 시트가 다 먹는다. 그래서 두 번 채운다:
① 기준만으로 몇 장이 필요한지 세고, ② **그 장수를 유지하면서** 시트당 개수 상한을 조여 다시 채운다.
상한을 조이면 그룹이 일찍 닫히기만 하므로 장수는 늘어날 수만 있다 —
목표치부터 올려 가며 **장수를 늘리지 않는 것들 중 가장 큰 시트가 가장 작은** 배분을 고른다.
(장수가 상한에 대해 단조롭지 않아 "처음 성공한 값"으로는 부족했다.)

라인 020(컴포넌트 41개) 실측:

| 요청 | 시트 | 컴포넌트 | 요소 |
|---|---|---|---|
| 이전 (2분할) | 2 | — | **383 / 33** |
| extent/2 | 3 | 14 / 14 / 13 | 78 / 73 / 61 |
| extent/3 | 4 | 10 / 10 / 10 / 11 | 54 / 62 / 51 / 54 |
| extent/4 | 5 | 14 / 8 / 14 / 2 / 3 | 78 / 42 / 74 / 7 / 17 |

### 선 겹침 회피 — 교차부 앞뒤 끊기 (2026-08-02)

등각도는 3D 를 한 장에 눌러 담으므로 **실제로는 떨어져 있는 배관이 화면에서 교차**한다.
그대로 두면 두 배관이 만나는 것처럼 보인다. 관례대로 **뒤에 있는 쪽을 끊는다**.

앞뒤는 화면 좌표로는 알 수 없다. 투영의 **영공간(= 보는 방향)** 으로 판정한다.
영공간 자체는 투영 행렬에서 나오지만 *부호(어느 쪽이 관측자인가)* 는 행렬에 없어
`IsoProjection.viewDirection` 으로 들고 있다(기본 `(1,1,1)/√3`).

끊지 않는 경우 — 이 가드가 없으면 멀쩡한 도면을 망친다:
1. **3D 에서도 같은 점**(1mm 이내)이면 진짜 분기점이다
2. 교차점이 구간 **끝점 가까이**(양끝 2% 이내)면 연결이 끊어져 보인다
3. 평행하거나 끝점만 스치는 경우

**실 코퍼스에는 진짜 교차가 없다.** 처음 세었을 때 22건 중 6건에서 교차가 잡혔지만,
전부 3D 거리 **0.0mm** — 올렛이 배관 중간에 붙은 **실제 분기점**이었다
(끝점이 아니라 중간에 붙어서 "끝점 공유" 검사에 안 걸렸을 뿐이다). 가드가 올바로 걸러낸다.
그래서 동작 검증은 합성 케이스로 했다 — 화면에서 교차하도록 좌표를 맞춘 두 배관
(X축 z=0, Y축 z=2000)에서 뒤쪽만 두 조각으로 끊긴다.

`display.crossingBreaks` 로 끌 수 있다(기본 켬).

### 심볼 겹침 — 확대 상세도 (2026-08-02)

경계가 겹치는 심볼끼리 묶어(union-find) 밀집 구간을 찾고, 본도면에는 원 + 이름(A, B…)을 씌우고
**확대본을 빈 자리에 따로 그린다**. 본도면 심볼은 지우지 않는다 — 상세도를 안 봐도 위치는 알아야 한다.

**두 번 크게 틀렸다.**

1. **처음엔 구간을 통째로 확대했다.** 심볼도 같은 배율로 커지니 겹침 비율이 그대로 —
   상세도가 그냥 **검은 덩어리**로 나왔다. 심볼은 크기를 유지하고 **위치만** 벌려야 분리된다.
   배율은 *가장 가까운 두 심볼이 symbolUnit×1.3 만큼 떨어질 때까지*로 정한다.
2. **반지름을 심볼 크기가 포함된 값에 곱했다.** 상세도가 부풀어 도면 폭이
   17.6m → **31.2m** 가 됐다(본도면이 상세도에 밀려남). 반지름은 **위치가 퍼진 범위**에
   배율을 곱하고, 다시 `symbolUnit × 2.2` 로 상한을 건다(넘으면 배율을 낮춘다).

자리는 라벨 배치기의 점유 정보로 찾는다 — 치수·주석이 다 놓인 **뒤에** 남은 빈 곳에 넣는다.
도면 안에 자리가 없으면 오른쪽 바깥에 쌓는다.

| 입력 | 상세도 | 도면 범위 변화 |
|---|---|---|
| PCF 001 | 0 (겹침 없음) | — |
| PCF 006 | 1 (2.9:1) | 없음 (도면 안에 들어감) |
| PCF 012 | 1 (13.2:1) | 없음 |
| IDF 014 | 2 (2:1, 5.3:1) | 8,198 → 9,503 (+16%) |
| IDF 012 | 4 (3.7~22.4:1) | 17,613 → 21,228 (+21%) |

`display.details` 로 끌 수 있다(기본 켬). 한 장에 최대 4개.
확대본 원은 id 접두사 `dtv`, 본도면 버블은 `dtb` 로 구분한다 —
"상세도가 본도면 위에 놓이지 않는다" 검증이 둘을 구분해야 한다.

### 심볼 겹침 측정 (상세도 도입 근거)

심볼끼리 경계가 겹치는 개수(실 코퍼스 + IDF):

| 입력 | 심볼 | 겹침 |
|---|---|---|
| PCF 001~022 | 4~13 | 대부분 0, 3건에서 1 |
| IDF 012 | 23 | **13** |
| IDF 014 | 12 | **10** |

IDF 쪽이 심한 이유는 **용접 간격 17mm 짜리 배관을 17m 도면에 그리기 때문**이다.
심볼 크기가 396mm 인데 간격이 17mm 라 균일 축척으로는 분리할 방법이 없다.
이건 배치로 풀 문제가 아니라 **상세도**로 풀어야 한다 — 위 절 참조.

### 용지 채움 — 표를 우측 칸에서 아래 띠로 (2026-08-02)

도면이 용지를 다 못 쓰는 원인은 **표 배치**였다. 우측 세로 칸(150mm)이 도면 영역을
`245 × 277`(세로로 긴 형태)로 만드는데 등각도 내용은 가로로 길다(가로/세로 1.3~2.4).
늘 가로에서 배율이 걸려 **세로가 31~63% 남았다.**

바꾼 것:
- 자재표·절단·용접 리스트를 **아래 띠에 가로로 나란히** 놓는다.
  세로로 쌓으면 띠가 높아지므로 나란히 둬서 띠 높이를 *가장 긴 표 하나*로 줄였다.
- 타이틀 블록은 띠의 오른쪽 끝(폭 110mm).
- **띠 높이는 설정값이 아니라 실제 표 내용만큼만** 잡는다(`tableBandMm` 은 상한).
  늘 최대 높이를 잡으면 표가 짧은 도면에서 종이가 그만큼 죽는다.
- 열이 많은 표에 폭을 더 준다 — 균등 분배하면 자재 설명이 다 잘린다.

배율 변화 (mm/도면mm, 클수록 크게 그려짐):

| 입력 | 이전 | 이후 | |
|---|---|---|---|
| PCF 001 | 0.0276 | **0.0417** | +51% |
| PCF 006 | 0.0212 | **0.0243** | +15% |
| PCF 012 | 0.1459 | **0.1808** | +24% |
| IDF 012 | 0.0139 | **0.0153** | +10% |
| IDF 014 | 0.0299 | **0.0488** | +63% |

잉크가 용지 안쪽(400×277)을 채우는 비율은 67~100% × 59~84% 가 됐다.
남은 여백은 내용과 용지의 **가로세로 비 차이** 때문으로, 균일 축소를 쓰는 한 없앨 수 없다.

**작업 중 잡은 것**: 띠 높이 계산이 `drawTable` 의 여유분(제목 1.4행 + 2행)과 어긋나
자리를 좁게 잡는 바람에 표의 행이 통째로 잘렸다. 식을 `(행수 + 3.4) × 행높이` 로 맞췄다.

> 스타일 항목 `sheet.tableColumnMm`(우측 칸 폭)은 `sheet.tableBandMm`(아래 띠 높이, 기본 70)로 바뀌었다.
> 예전 값이 저장돼 있어도 무시되고 기본값이 쓰인다.

**extent/4 는 고르게 못 나눈다.** 상한을 13 이하로 조이면 7장으로 튀고 14 부터 5장이 된다 —
시트당 담을 범위가 컴포넌트 하나 크기에 가까워 균형을 잡을 여지가 없다.
이때는 **장수를 늘리지 않는 쪽**을 택한다. 실제 경로는 밀도가 해소되는 최소 장수를 쓰므로
보통 2~3장이고, 거기서는 완전히 고르다.

### 문자 최소 크기를 기준으로 쓰지 않은 이유

처음에는 "문자가 기준 크기보다 작아지면 나눈다"로 잡았으나, **재 보니 그 조건은 걸리지 않는다.**
심볼 크기가 `도면 대각선 × unitRatio` 로 비례해 축소 배율과 상쇄되기 때문이다:

| 입력 | 내용 범위 | 용지 위 문자 높이 |
|---|---|---|
| PCF 012 | 1,679 × 1,274 | 3.49~6.28 mm |
| PCF 006 | 11,563 × 8,994 | 3.80~6.84 mm |
| IDF 012 | 17,613 × 13,232 | 4.19~7.54 mm |

도면이 10배 커져도 종이 위 글씨는 그대로다. 나빠지는 것은 크기가 아니라 **밀도**다.
로드맵에 적어 두었던 "큰 라인에서 글씨가 작아진다"는 관찰이 틀렸다.

`createdb isoflow` 후 기본 프로파일로 기동해 전 경로를 확인했다. 검증용 2건은 삭제해 원복했다.
